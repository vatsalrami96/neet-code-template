# Primers

One per section, written by Claude before the section's first problem, read by the candidate in about ten minutes.
File name is the section id: `01-arrays-hashing.md`, `02-two-pointers.md`, ...

A primer is a gate, not a lecture. Required sections, in this order:

1. **Before you start.** What you must already be comfortable with. One to three bullets.
2. **The pattern and its templates.** The one to three shapes this section is about, each with the *invariant*
   that makes it correct (the sentence you would say to convince an interviewer). Point to `reference/templates/`
   where one exists.
3. **How to recognize it.** The words in a problem statement that should trigger this pattern.
4. **Classic mistakes.** Three to five, concrete.
5. **Complexity you should expect.** The typical time and space, and what "too slow" looks like here.
6. **Warm-ups.** Two questions, five minutes each, answered in chat before the first problem. Not LeetCode problems;
   small checks that the fundamentals are there. Claude grades them and, if both fail, spends 20 minutes on
   fundamentals before opening the first problem.
7. **The problems, in order.** Every problem in the section with one line on what it teaches and a note when it is a
   prerequisite for a later one.

Keep it under two screens. Corrections are appended under a `## Corrections` heading, never rewritten.
